# ADR: `go mate` を USI 仕様の df-pn 詰み探索にする

- Date: 2026-10-21
- Scope: rshogi-core (`crates/rshogi-core/src/mate/dfpn/`、`search/`)、rshogi-usi
- Related: なし

---

## 1. 背景 (Context)

`go mate N` は UCI 流の実装だった。`N` を手数として `LimitsType::mate` に入れ、通常探索が
`N` 手以内の詰みスコアを見つけたら止めて `bestmove` を返す。USI 仕様の `go mate` は
引数がミリ秒 (または `infinite`) で、応答は `checkmate <手順>` / `checkmate nomate` /
`checkmate timeout` である。USI 仕様どおりに `go mate 2000` を送る GUI・ツールでは
「2000 手以内の詰み」と解釈されて、事実上の無制限探索になっていた。

また、詰めろの判定 (手番を相手に渡した局面が詰むか) に使える詰み専用探索が無かった。
通常探索の詰みスコアは選択的な枝刈りを含むので、不詰の判定には使えない。

## 2. 決定事項 (Decision)

### 2.1 `go mate` の意味を USI 仕様に変える

- `go mate <ミリ秒>` / `go mate infinite` / `go mate` (= infinite) で df-pn を別スレッドで走らせ、
  `checkmate <手順>` / `checkmate nomate` / `checkmate timeout` を返す。`stop` で打ち切ると
  `checkmate timeout`。置換表サイズは USI オプション `MateHashMB` (既定 64)。
- UCI 流の経路 (`LimitsType::mate`、`mate_within_limit`) は `go mate` 以外に呼び手が無いので削除した。

### 2.2 問題の定義

- 与えられた局面から手番側が王手を続けて詰ませるか。対局履歴 (`position ... moves`) は見ない。
  探索経路上の局面に戻る手順は攻め方の失敗 (連続王手の千日手は攻め方の負け、それ以外の反復も
  詰みの根拠にならない) として扱う。
- 手番側が王手されている局面も解く (王手を外しつつ王手をかける手から)。「王手中なら nomate」は
  逆王手で詰む局面を不詰と言ってしまうので採らない。
- 攻め方・受け方とも不成を含めて生成する。受け方は合駒を含む全応手。打ち歩詰めの歩打ちは
  攻め方の手にならない。無駄合いの枝刈りはしない。
- 結果は詰み / 不詰 / 打ち切りの 3 値。時間・ノード数・停止・深さ上限は必ず打ち切り (Unknown) で、
  不詰に混ぜない。詰み手順は最短を保証しない (探索とは独立に、合法・王手の連続・終端が詰みで
  あることを検証してから返す)。

### 2.3 探索の方式

参考実装 (YaneuraOu `mate_dfpn.hpp`、cshogi の dlshogi 由来 df-pn と GPS 将棋 (OSL) 移植版、
KomoringHeights) を比べ、置換表型の df-pn を KomoringHeights の設計に沿って書いた。

- YaneuraOu `mate_dfpn.hpp` は探索木をメモリに保持する最良優先探索で、メモリがノード数に比例する。
  置換表 (`MateHashMB`) でメモリを抑える要件に合わない。
- OSL 移植版 (約 1 万行) は持駒優越・証明駒・証明流用などを多く持つが、OSL 固有の手生成順・駒番号に
  依存し、移植の規模が大きい。
- dlshogi 由来版は受け方の不成を生成せず、深さ上限を不詰として扱うので採らない。

正しさに関わる設計:

- 子の pn/dn は親のフレーム内の配列にだけ持ち、子の探索の戻り値でだけ更新する (局所展開)。
- 経路上の局面への反復 (と、同じ盤面で攻め方の持駒が劣る劣等局面) は、その経路での不詰とし、
  依存する祖先の深さ (ループの始点) を付けて親に伝える。始点まで戻ったら通常の不詰として確定させる。
  条件付きの不詰は置換表に書かない (GHI 問題の回避)。子の展開時に反復を判定して先に確定させる。
- TCA (Kishimoto 2010) で、浅い深さで書かれた未確定値を使う子があるときは閾値を延長する。
  局所展開だけでは、循環を通って膨らむ未確定値で停滞する (抽象 AND/OR グラフ 3,000 個の検査で
  TCA なしは 32 件が打ち切り、TCA ありは 0 件)。
- 打ち切りは `Result` で探索全体を中断する (上限に達したノードに値を返させない)。
- 詰み手順は、手順上の局面を詰み手数の上限付きで探索し直して復元する。置換表の詰みは経路に
  依存しないので、上限なしで辿ると手順の途中の局面に戻る詰みを選んで循環しうる。

範囲外 (計測で必要になった順に検討): 証明駒・反証駒と持駒優越の置換表再利用、無駄合いの扱い、
DAG の二重計数対策、詰み手数の最短化、並列化、通常探索からの呼び出し。

## 3. 帰結 (Consequences)

- `go mate N` を「N 手以内の詰み」として使っていた呼び出し側は、意味が変わる (引数はミリ秒になり、
  応答は `bestmove` でなく `checkmate`)。
- 局面の同一性は 64bit のハッシュキーで判定する。衝突による誤りは確率的にのみ排除される。
- 対局履歴を見ないので、実戦の千日手規則 (同一局面 4 回) とは一致しない。詰めろ判定のように
  手番を反転した仮想局面を解く用途を主に想定している。
