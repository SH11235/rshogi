# book_backprop

`book_backprop` は YANEURAOU-DB2016 テキスト定跡 `.db` の候補手評価値を、book 内の子局面から親方向へ逆伝播するツールです。千日手を考慮した後退解析で値を求め、既存手の `count` / `ponder` / 探索 `depth` は保持して `value` を更新します。手の補完は `--add-transposition-moves` を指定したときだけ行います。

## 使い方

```bash
cargo run -p tools --release --bin book_backprop -- \
  --book in.db \
  --out out.db \
  --draw-value-black -70 \
  --draw-value-white 0 \
  --merge min \
  --report report.md
```

必須オプション:

| オプション | 説明 |
|---|---|
| `--book <PATH>` | 入力 `.db` |
| `--out <PATH>` | 出力 `.db` |

任意オプション:

| オプション | 既定値 | 説明 |
|---|---:|---|
| `--draw-value <CP>` | `0` | 千日手の値 (手番の側から見た値)。先手・後手とも同じ値にする |
| `--draw-value-black <CP>` | `--draw-value` | 先手を自分として解くときの千日手の値。エンジンの `DrawValueBlack` に当たる |
| `--draw-value-white <CP>` | `--draw-value` | 後手を自分として解くときの千日手の値。エンジンの `DrawValueWhite` に当たる |
| `--merge <MODE>` | `min` | book 内子局面からの伝播値と既存ラベル値の合成。`min` または `replace` |
| `--report <PATH>` | なし | Markdown レポートの出力先 |
| `--skip-unusable-moves` | off | 非合法手と `none` 行を局面の best (と best 変化の集計) から除く。行自体は値を変えずに書き出す |
| `--skip-unsearched-children` | off | 未探索の子を値 0 と扱って親の実探索値を上書きしないため、候補手があり全行 `depth=0` の子への辺を除く。直接・反転キーの両方に適用し、`value` は判定に使わない。候補手の無い子は除外しない。入力時に全行 `value=0 depth=0` の局面は出力行も保持する |
| `--add-transposition-moves` | off | 異なる手順で同一局面へ到達するときに候補手を共有できるよう、book 内の既知局面へ進む未登録の合法手を補完する |

値の反復をやめたので、以前の `--max-iters` はありません。以前の版で作った結果を再現するには、その版の `book_backprop` を使ってください。

## 伝播規則

局面キーは SFEN の ply を除いた board / turn / hands の 3 フィールドです。出力の `sfen` 行には入力側の ply を残し、同一キーが複数ある場合は最小 ply の行を代表として使います。

各 book 手の子局面は次のように扱います。

| 子局面 | 扱い |
|---|---|
| book 内に直接存在 | 子局面の値を伝播する |
| 直接 miss だが先後反転キーが book 内に存在 | 反転した子局面の値を伝播する |
| book 外 | 既存 `value` を葉の値とする |
| 非合法手 | stderr に警告し、既存 `value` を葉の値とする |

子局面との照合は盤・手番・持ち駒で行い、合流先はそれを正規の SFEN で書いた key の局面です。持ち駒の並びなどが正規の表記と違う key の局面は、同じ局面でも合流先にならず、別の局面として扱います。

歩・香の最終段、桂の最終二段への打ち・不成も非合法手として除外します。子局面が book 内に存在していても、その手の既存 `value` を維持します。合法な不成は通常の手と同様に逆伝播します。

既定では非合法手と `none` 行の既存 `value` も best の候補に含みます。`--skip-unusable-moves` を指定するとこれらを除き、合法手だけで best を決めます (合法手が無い局面の値はその手番の千日手の値)。

### 先手・後手をそれぞれ自分として解く

逆伝播は、先手を自分とした回と後手を自分とした回の 2 回解きます。各回は千日手の値を自分の側の値 (`--draw-value-black` / `--draw-value-white`) に固定した 2 人零和の問題で、相手から見た千日手の値はその符号反転です。先手番の局面の値は先手の回から、後手番の局面の値は後手の回から書き出します。対局のエンジンが先手番で千日手を避け (`DrawValueBlack=-70`)、後手番で避けない (`DrawValueWhite=0`) なら、同じ値を渡すとエンジンの判断と揃います。

各回は次の規則で値を決めます。

- book 内の循環に留まり続ける手順は千日手で、自分の千日手の値になる。
- 連続王手の千日手は、王手をかけ続けた側の負け (-32000) になる。
- 値は、高い値から順に「その値以上を保証できる局面」を葉の側から確定して求める (YaneuraOu の `makebook peta_shock` と同じ後退解析)。王手をかけ続けられる循環の部分だけを繰り返し調べるので、入力によらず終わる。
- 双方が王手をかけ続ける循環は対応範囲外で、エラーにして book を書き出さない。
- 千日手の値は -30000〜30000 で指定する。範囲外はエラーにする。

計算量は、通常の局面では辺の数に比例します。王手をかけ続けられる循環の部分は、閾値ごとに、また確定が進むたびに調べ直すので、その部分の大きさの 2 乗程度までかかることがあります (YaneuraOu と同じ)。

規模の目安: 225 万局面・1,610 万手の定跡 (反転キーで合流する辺 253 万) は、1 スレッドで `replace` が約 95 秒・ピークメモリ約 0.93 GiB、`min` が約 105 秒・約 1.1 GiB でした。メモリは局面数・手数にほぼ比例します。定跡のグラフ作り (局面と手の行き先の引き当て) は局面の塊ごとに rayon のスレッドで並べ、結果を元の順に連結するので、出力はスレッド数によりません。スレッド数は `RAYON_NUM_THREADS` で変えられます (既定は全コア)。

メモリを抑えるため、入力の文字列は局面の代表 SFEN だけを持ち、入力を 3 回読みます (局面の一覧、手の値と指し手、書き出し)。実行中に入力が書き換わったことを検出したら、エラーにして書き出しません。出力は同じディレクトリの一時ファイルに書いてから置き換えるので、`--out` に `--book` と同じパスも指定できます。

### `--merge`

| mode | 自分の手 | 相手の手 |
|---|---|---|
| `replace` | 伝播値 | 伝播値 |
| `min` | `min(既存ラベル値, 伝播値)` | 伝播値 |

`replace` は book 内の手を全て信じ、相手も book の手しか指さないとみなします。

既定の `min` は、自分は book どおりに指し、相手は book 外も指せるとみなします。自分の手の既存ラベル値は book 外の応手まで読んだ探索の値なので、自分の手の値はそれを上限にします (相手が book 外で咎められる)。相手の手は抑えません。相手の手のラベルは自分が book 外の手で咎める前提の値ですが、自分は book どおりに指すので、その咎めは起きないためです。各回で自分と相手が入れ替わるので、書き出す行はどれも、その局面の手番の側の手として自分のラベルで抑えた値になります。補完手には探索ラベルがないので `min` でも抑えません。

### 同値手の補正

値を保つ手のうち、勝ち (千日手の値以上) の局面は短い手順で、負けの局面は長い手順で、葉か手の無い局面へ届く手を選びます。手順の長さは値を保つ手だけで数え、循環から抜けられない局面は長さが決まらないので、後退解析で得た保証手をそのまま使います。

書き出し時だけ、best と同値の行のうち、選んだ手と、それと同じ長さで出口へ届く手を残し、他を `max(value-1, -32000)` にします。同値の遠回りや延々と同じ循環を選ぶことを避けるためです。合法値の下限 -32000 は据え置き、-32001 (-INFINITE) を生成しません。0 から -1 への補正は適用します。この補正は親へ伝播しません。**手順の長さを book の depth へ書くことはありません。** `count` による出力順にも変更はありません。

同値の補正は book 外の合法な葉手にも適用します。非合法手・`none` 行と、`--skip-unsearched-children` で辺を除いた親の手は補正からも除外し、既存値を保持します。出力は決定的で、局面は SFEN key 昇順、手は `count` 降順から USI 昇順で書き出します。

### 書き出す値の保証検査と同値手の制限

書き出す前に、出力の値どおりに指したとき循環で値の約束が破られないかを、先手・後手をそれぞれ自分として検査します。自分は各局面で出力値が最大の手 (同値補正で -1 されなかった手) のどれを選んでもよく、相手は全手を選べるものとして、次のどちらかの局面を探します。

| 検査 | 破られる条件 |
|---|---|
| 自分の連続王手 | -32000 より良い値なのに、自分の手が全て王手になる循環 (連続王手の千日手で反則負け) へ相手が持ち込める |
| 千日手への逃げ | 自分の千日手の値より良い値なのに、相手が王手をやめながら続けられる循環へ持ち込める |

見つかった局面では、残していた同値手を -1 して後退解析の保証手だけを残し、検査をやり直します。その局面数は stderr と report に出します。保証手だけにしても破られる局面が残ればエラーにし、book と report は書き出しません。エラーには該当局面の数と先頭 5 局面のキーを出します。

相手の手は探索ラベルの良し悪しを問わず全て数えます。ラベルが相手の負けを示していても、book どおりに指す側は book 外の咎める手を指さないので、相手はその手で循環を続けられます。値の約束は、自分の手番の局面の値で見ます。「持ち込める」は途中の局面の値を問わず、上の手の選び方でその循環へ届くかで判定します。

循環は局面と実際の手番の組で判定するので、反転キーで合流した辺を含む循環も実際の手番どおりに扱います。反転キーで合流した局面は 1 行に 1 組の値しか持てません。そこで反対の向きでも、保存されている向きの最大値の行のどれを指してもその向きで解いた値を保つかを確かめ、保たない局面があればエラーにして book を書き出しません。千日手の値が先後で同じなら両方の向きは同じ問題なので、この食い違いは起きません。保証検査は、保存されている向きから指して届く反対の向きの局面も数えます。

検査するのは逆伝播に使った辺だけです。book 外への手、非合法手、`none` 行は子局面への辺を持たず、`--skip-unsearched-children` で除いた未探索の子への辺も辿りません。`--skip-unusable-moves` のときは、非合法手と `none` 行を「書き出し値が最大の手」の判定からも除きます。未探索局面の 0/0 ラベルは探索で置き換わる前提のデータなので、その先の循環は保証の対象外です。

### 合流手の補完と未探索保護

`--add-transposition-moves` は全合法手を調べ、直接キーまたは反転キーで book 内に存在する子への未登録手を追加します。追加手の値は子局面からの伝播値 (上記の同値補正も適用)、`count=0`、`ponder=none`、`depth=1` です。追加手に既存探索ラベルはないため、`min` でも仮の 0 を上限として使いません。depth 1 は未探索 0/0 と区別する固定値で、実探索した深さや伝播距離を表しません。

`--skip-unsearched-children` が有効な場合、全行 `value=0 depth=0` だった入力局面は値も含めて行を保持し、補完もしません。子が探索済みでも、親を探索済みへ偽装しないためです。`book_mine` の `PositionEntry::is_unexplored` が引き続き葉として列挙できることを保ちます。

## レポート

`--report` を指定すると Markdown で以下を出力します。

| 項目 | 内容 |
|---|---|
| Summary | merge mode、先手・後手の千日手の値、ノード数、手数、更新手数、book 内辺数、flip 合流辺数、非合法手数 |
| Value deltas | `|Δ|` の p50 / p90 / max とヒストグラム |
| Propagation depth | 局面グラフの強連結成分を縮約した DAG で、葉から何段伝播したかの分布 |
| SCC | 非自明 SCC 数、最大サイズ、千日手の値になった SCC 内手数、王手をかけ続けられる循環の状態数、保証手だけを残した局面数 |
| Top changed nodes | 旧 best と新 best の差が大きい上位 20 局面 |
